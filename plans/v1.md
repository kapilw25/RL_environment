# 🎮 RL Environment Plan: Build an Env, Then Beat 5 Public Benchmarks

> **Goal:** A simple, mostly-CPU plan to (1) build an RL environment and (2) prove a model
> trained with our recipe improves its score on **at least 5 public benchmarks**.
>
> **Strategy:** Two phases, run in sequence, one per hardware target you own.

## 📊 At a Glance

| | 🖥️ **Phase 1 (CPU)** | 🚀 **Phase 2 (GPU)** |

| **Hardware** | Apple M1, no CUDA | RTX 6000 PRO, 96 GB |

> benchmarks"* (each score rising well above a random / base reference).

# 🖥️ Phase 1: CPU, Gymnasium + Stable-Baselines3 (do this first)

### ⚡ Setup

```bash
cd RL_env/phase1_cpu
python3 -m venv .venv && source .venv/bin/activate
pip install "stable-baselines3>=2.8.0" gymnasium minatar tensorboard matplotlib pyyaml
```

### 🏗️ Step 1: Build the custom environment (`envs/gridworld_env.py`)

- Subclass `gymnasium.Env`. Simple **5x5 GridWorld**: agent starts in a corner, must reach a
  goal cell. `Discrete(4)` actions (up/down/left/right), a `Box`/`Discrete` observation of
  position, reward `-0.01` per step and `+1` at the goal, terminate on goal or step cap.
- Implement `__init__` (define `action_space`, `observation_space`), `reset(seed)`, `step`,
  and optional `render`. Register via `gymnasium.register`. Follow the Gymnasium custom-env
  tutorial pattern (the canonical "build your own env" shape).
- 🎯 This is the artifact that satisfies **"build an RL environment."**

> ✅ **Verify:** `gymnasium.utils.env_checker.check_env` passes + a quick random-policy rollout runs.

### 🔁 Step 2: One training recipe (`train.py`)

- A single function takes an `env_id` and trains **PPO** with fixed hyperparameters, so the
  **same recipe** is reused across the custom env and all 5 benchmarks (the "one recipe").
- ⚠️ MinAtar observations are small `10x10xC` image tensors. SB3's default `NatureCNN` is built
  for large frames and **fails on 10x10** → provide a **tiny custom CNN** feature extractor
  (`BaseFeaturesExtractor`, 1 to 2 small conv layers) OR wrap with `FlattenObservation` +
  `MlpPolicy`. Recommended: the small CNN.
- Log to tensorboard; save each model under `results/`.

### 📏 Step 3: Evaluate + benchmark (`evaluate.py`, `benchmark.py`)

- `evaluate.py`: run N (e.g. 30) greedy episodes → mean ± std return; also run a **random
  policy** as the reference baseline.
- `benchmark.py`: loop the recipe over all 5 MinAtar games, save a learning-curve PNG each,
  and emit the results table. **This table is the Phase 1 result.**

#### 🎯 Phase 1 benchmark targets

| 🕹️ Game | Env ID | Random (approx) | 📈 Published DQN baseline |
|---|---|---|---|
| Breakout | `MinAtar/Breakout-v1` | ~0.5 | **27.1** |
| Freeway | `MinAtar/Freeway-v1` | ~0 | **55.9** |
| Asterix | `MinAtar/Asterix-v1` | ~0.5 | **13.6** |
| Seaquest | `MinAtar/Seaquest-v1` | ~0 | **38.0** |
| SpaceInvaders | `MinAtar/SpaceInvaders-v1` | ~2.5 | **188** |

### ⏱️ Compute budget (all CPU on M1)

| Mode | Budget / game | Time / game | Goal |
|---|---|---|---|
| 🏃 **Fast demo** (start here) | ~500k to 1M steps | ~10 to 30 min | score clearly & monotonically above random on all 5 |
| 🐢 **Full baseline match** | ~5M frames (paper budget) | ~1 to 3 hr | approach the published DQN numbers (overnight run) |

> 💡 The fast-demo budget alone already satisfies *"improving on 5 public benchmarks"* (well above random).

### ✅ Phase 1 verification (the headline result)

1. `python train.py --env-id GridWorld-v0` → return rises to near `+1` (proves the custom env works).
2. `python benchmark.py` → a 5-row table where **our score ≫ random** on every game (and, at
   full budget, within range of the published DQN baselines) + 5 rising learning curves.

> 🛟 **Fallback** if MinAtar has any friction on Python 3.13: swap in the classic set
> (`CartPole-v1` solved=475, `LunarLander-v2` solved=200, `Acrobot-v1`, `MountainCar-v0`,
> `Pendulum-v1`). Same recipe, same table format, runs in minutes on CPU.

# 🚀 Phase 2: RTX 6000 PRO 96 GB, RLVR with GRPO (do this second)

### ⚡ Setup (on the GPU box, Linux + CUDA)

```bash
cd RL_env/phase2_gpu
python -m venv .venv && source .venv/bin/activate
pip install verifiers trl transformers peft accelerate datasets vllm lm-eval
```

> 🛟 TRL `GRPOTrainer` is the fallback if the verifiers trainer gives trouble; both do GRPO.

### ✅ Step 1: Build the verifiable RL environment (`environment/math_env.py`)

- **Verifiable env:** prompt = a problem (start with GSM8K-style math), the model generates a
  chain-of-thought answer, and a **rule-based verifier** extracts the final answer and returns
  reward `1.0` if correct else `0.0` (optionally a small format reward). Deterministic and
  human-free → cheap and reproducible (this is **RLVR**).
- ⚠️ **Design point for the "5 benchmarks" headline:** RL on math *alone* reliably lifts
  math-aligned evals (GSM8K, MMLU-STEM, ARC) but may **not** move HellaSwag / TruthfulQA.
  To lift a broader set, make the env **multi-skill**: mix math with a couple of other
  verifiable tasks (multiple-choice science with exact-match, short factual QA). Keep it small.

### 🔁 Step 2: Train (`train_grpo.py`)

- **Base model:** Qwen2.5-0.5B-Instruct (or 1.5B). **LoRA** adapters (peft) so "very little GPU
  compute" holds even on the big card.
- **GRPO:** group size ~8, a few hundred to ~1 to 2k steps over a small train subset (1 to 2k
  problems). **vLLM** for fast rollouts. Fits 96 GB with lots of headroom; runtime is hours.

### 📊 Step 3: Evaluate on 5 public benchmarks (`eval_harness.sh`)

Run lm-evaluation-harness **twice**: once on the base model (**pre**), once on the GRPO-tuned
model (**post**, base + merged LoRA). Pre-scores are the reference baseline; post-scores are our model.

| 🧪 Benchmark | lm-eval task | Tests |
|---|---|---|
| GSM8K | `gsm8k` | grade-school math |
| MMLU | `mmlu` | broad knowledge |
| ARC-Challenge | `arc_challenge` | science reasoning |
| HellaSwag | `hellaswag` | commonsense |
| TruthfulQA | `truthfulqa` | truthfulness |

### ✅ Phase 2 verification (the headline result)

- A 5-row table: `benchmark | base (pre) | GRPO (post) | Δ`. **Success** = post > pre on the
  target-aligned benchmarks with no material regression on the others; with the multi-skill env,
  aim for improvement on **all 5**.
- 🚦 **Sanity gate before the full run:** eval base model on a 100-example GSM8K slice, train
  50 GRPO steps, re-eval the slice, confirm the number moves up. Only then launch the full run.

# ⚠️ Risks & Caveats

- 🖥️ **Phase 1:** SB3 default CNN fails on 10x10 MinAtar frames → the tiny custom CNN (or
  flatten + MLP) is required. Matching published DQN baselines needs the full ~5M-frame budget;
  the fast-demo budget only guarantees "well above random."
- 🚀 **Phase 2:** single-domain RL may not lift all 5 diverse NLP benchmarks → use the
  multi-skill verifiable env and pick benchmarks that overlap the training skills. Keep model
  small + LoRA to honor the low-compute goal.
- 🧷 Keep the two phases in **separate venvs** (CPU M1 vs CUDA box); do not share requirements.
